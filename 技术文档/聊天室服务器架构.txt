聊天服务器架构详细设计说明书（完整版、可直接当示例 / 作业文档）
一、项目概述
本项目实现一套基于 C/S 架构的多人即时聊天系统服务端，采用 C++ + Windows Socket + MySQL 技术栈开发。
服务端采用多线程并发模型，支持多客户端同时在线连接、实时消息转发、聊天记录持久化存储、多条件历史消息查询、用户账号注册与登录校验。
整体架构模块化解耦，网络通信、业务逻辑、数据持久层完全分离，结构清晰、扩展性强，可无缝对接控制台客户端、后续 Qt 图形化客户端，适合作为网络编程、数据库开发、并发程序设计综合示例。
二、整体架构总览
系统采用三层分层架构：
网络通信层：基于 Socket 完成 TCP 连接管理、数据收发、字节流处理
业务逻辑层：指令解析、功能分发、消息处理、请求响应封装
数据持久层：基于 MySQL 数据库，实现用户数据、聊天数据增删查改
架构流转流程
plaintext
多客户端TCP连接 
↓
服务端Socket监听端口 → 接收客户端连接 → 为每个客户端分配独立子线程
↓
线程循环接收客户端完整报文（修复空格截断、字节接收不全问题）
↓
业务层统一报文解析，识别操作指令
↓
调用对应业务接口，按需访问数据库层
↓
封装响应数据，通过TCP回传给客户端
↓
客户端解析回包，展示消息、时间、查询结果
三、核心模块详细设计
（一）网络通信模块（传输层）
通信模型
采用 TCP 面向连接可靠传输协议，基于流式 Socket 通信
服务端主线程负责循环监听端口，持续接受新客户端接入
采用一客户端一线程 并发模型，隔离不同用户会话，互不阻塞
核心功能
端口监听、三次握手连接建立、异常断线检测与资源释放
自定义完整报文接收机制：解决原生 recv 缓冲区截断、空格丢失、特殊字符接收不全问题，保证带空格完整时间 yyyy-MM-dd HH:mm:ss、含空格聊天内容完整传输
字节数据与字符串编码转换，统一使用 UTF-8 格式收发
循环接收、边界判定、粘包简易处理，保证报文完整性
通信特点
面向长连接，客户端连接成功后可连续发送多条请求
无固定数据包长度，依靠自定义协议关键字与换行符作为分割
（二）业务逻辑模块（逻辑层，核心类：chat）
设计思想
将所有业务请求统一收敛，通过指令分发机制解耦，新增功能只需增加分支判断，符合开闭原则。
核心核心函数与功能
message_divide()：全局统一入口
接收客户端原始报文，分割指令头与参数体，自动识别客户端操作类型，分发对应处理逻辑。
支持五大业务指令：
账号登录：校验客户端账号密码，匹配数据库用户表数据
账号注册：接收注册信息，写入用户数据表，完成合法性校验
实时消息发送：接收用户名、消息内容、时间戳，组装标准格式报文
按数量查询历史消息：接收截止时间 + 查询条数，倒序查询近期聊天记录
按时间区间查询历史消息：接收起始时间 + 结束时间，区间筛选聊天记录
消息组装与封装
统一规定前后端交互数据格式，统一拼接 &key=value 键值对格式，保证客户端解析统一、便于调试与维护。
（三）数据库操作模块（数据层，核心类：datebase）
数据库环境
数据库：MySQL
连接方式：官方 C 语言 API 原生连接
数据表：用户信息表、聊天消息记录表
核心功能设计
数据库长连接：服务端启动时初始化数据库连接，全程复用，减少频繁连接开销
聊天记录持久化：
接收业务层传入的批量消息字符串，按行解析用户名、消息内容、完整时间戳，拼接 SQL 语句批量插入数据库
时间格式兼容处理：
数据库字段 ctime 设计为 DATETIME 类型，完整保存日期 + 时分秒，彻底解决仅存日期、时间丢失问题；
修复前期 Socket 接收截断导致时间空格丢失、时分秒无法入库的核心 BUG。
多条件数据查询：
根据指定截止时间 + 条数，限量倒序查询
根据起止时间区间，范围筛选查询
获取数据库最新一条聊天记录时间，作为客户端同步基准时间
数据表设计
1）聊天消息表 chat_message
| 字段名 | 字段类型 | 约束 | 作用 |
|--------|----------|------|------|
| username | varchar (50) | 非空 | 消息发送者用户名 |
| message | text | 可为空 | 聊天消息内容 |
| ctime | datetime | 非空 | 消息发送完整时间戳 |
2）用户账号表
存储用户名、密码、个人备注、注册时间等基础信息，用于登录注册业务校验。
（四）多线程并发设计
线程划分
主线程：负责 Socket 初始化、端口绑定、循环监听客户端连接
子工作线程：每接入一个客户端，独立创建专属通信线程
线程隔离：每个客户端的数据接收、指令解析、数据库查询、响应回写全部在独立子线程中完成
线程安全与资源管理
单线程独立处理单客户端请求，避免会话数据混乱
客户端断线自动触发线程退出、套接字资源关闭，防止内存泄漏
数据库操作为串行单连接访问，保证数据操作安全，无并发读写冲突
四、自定义通信协议设计（重点示例亮点）
为适配聊天业务，设计轻量自定义文本协议，可读性强、调试简单、跨客户端兼容。
请求报文通用格式
plaintext
指令&参数1=内容&参数2=内容&参数3=内容
实际业务报文示例
实时发送消息：
send_message&username=user1&message=你好&ctime=2026-04-27 15:30:20
按数量查询历史：
find_message_num&last_time=2026-04-27 15:30:20&num=10
按时间区间查询：
find_message_time&first_time=2026-04-01 00:00:00&last_time=2026-04-27 23:59:59
响应报文格式
统一以指令&开头，拼接多条消息键值对，换行分割单条记录，方便客户端循环解析。
五、核心问题优化与 BUG 修复（项目完善性体现）
解决 Socket recv 字节接收不完整问题
原生短缓冲区接收导致空格后数据截断，时间戳 yyyy-MM-dd HH:mm:ss 仅保留日期，通过改造循环接收、完整读取缓冲区，实现含空格特殊字符完整传输。
解决 MySQL 时间入库不完整问题
规范数据库字段类型为DATETIME，配合前端完整时间传输、服务端无截断解析，实现完整时间持久化。
完善异常处理
SQL 执行失败、报文格式错误、参数缺失、客户端异常断开，均做捕获与日志输出，程序稳定不崩溃。
六、系统运行完整流程
服务端启动，初始化 Socket 与 MySQL 数据库连接，绑定端口开始监听；
客户端发起 TCP 连接，服务端接受连接并创建独立子线程；
客户端输入操作指令，按照自定义协议组装报文发送；
服务端子线程完整接收全部数据，交由业务层指令解析函数；
根据解析出的操作类型，调用对应数据库接口完成查询 / 写入；
业务层统一封装响应结果，通过 TCP 套接字回发给客户端；
客户端接收响应数据，解析并展示聊天内容、时间、查询记录；
客户端下线或异常断开，服务端自动回收资源，子线程正常销毁。
七、架构优势与拓展性
模块化程度高
网络、业务、数据三层完全解耦，单独修改某一层不影响其他模块，代码复用率高。
并发能力稳定
多线程模型支持多人同时在线聊天，满足基础即时通讯场景。
跨客户端适配
纯文本自定义协议，无平台限制，可对接控制台客户端、Qt 图形客户端、Windows/Linux 端。
功能可快速拓展
可后期无缝新增：群聊、离线消息、用户头像、文件传输、心跳保活、日志系统等功能。
